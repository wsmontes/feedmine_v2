# The same-container path, attempted first and BLOCKED by a case collision (see README.md):
#   V1 writes "Library/Application Support/Feedmine"; V2 opens "Library/Application Support/FeedMine".
#   The host volume is case-insensitive (one inode for both spellings) but the app's own process is
#   not: measured inside the running app with lldb —
#     expr -l swift -- FileManager.default.fileExists(atPath: ".../Application Support/Feedmine/user.sqlite")  => false
#     expr -l swift -- FileManager.default.fileExists(atPath: ".../Application Support/FeedMine/user.sqlite")    => true
#     expr -l swift -- try? FileManager.default.contentsOfDirectory(atPath: ".../Application Support")            => ["FeedMine"]
#   With the directory spelled "Feedmine", V2 Release starts, writes nothing and shows
#   "Não foi possível carregar suas fontes." (AppComposition.swift:527 — the catch around
#   RuntimeDatabase construction). Renaming the directory to "FeedMine" makes V2 start, but then
#   LegacyV1Upgrade's first candidate ("…/Feedmine/user.sqlite") is the case-variant that no longer
#   resolves, so the run reports no legacy container and writes no receipt.
#   Both directions measured; the rehearsal therefore used V2's SECOND documented candidate,
#   Documents/user.sqlite (V1's pre-1.0 location, LegacyV1Upgrade.candidateUserStateURLs), by moving
