## 2. Resumo executivo — o que muda para o leitor

**Mudança importante, mas incompleta:** PR #8 identifica com testes deliberadamente RED uma contradição concreta: o Runtime mantém **todas as cartas antigas como itens apresentados** para não deslocar o scroll, mas decodifica imagens somente na banda próxima da âncora. Assim, uma carta antiga com layout de imagem pode integrar a lista entregue à UI com **image == nil**, contrariando a regra de 17/out: **nenhum card image-bearing pode atravessar a admissão sem pixels prontos**. Isto é um **conflito estático comprovado entre implementação e contrato**, não uma observação de vídeo/iPhone nesta execução. É P0 de prontidão visual, mesmo que a geometria continue estável.

**Há melhorias locais reais de código:** a nova versão limita re-decode aos IDs com pixels liberados, preserva a possibilidade de recuperação quando o arquivo local reaparece, evita re-decode em 60 callbacks repetidos, exclui cards text-only do registro de pixels liberados, reduz writes de exposição do mesmo card e não consome evidência de viewport antes de uma escrita SQLite bem-sucedida. Essas são **alterações estáticas verificadas**, com testes escritos; **não** são testes PASS nem uma solução completa do render-ready.

**O maior risco arquitetural é corrigir o placeholder destruindo o B05:** simplesmente remover da lista os 741 cards antigos sem bitmap pode fazer a tela saltar, produzir falso começo/fim ou perder a volta ao primeiro card; decodificar 766 imagens no warm start destrói custo e memória. A solução deve distinguir **história publicada e navegável** de **janela efetivamente render-ready apresentada**, dentro dos owners Runtime/Presentation existentes, com âncora/identidade estáveis e materialização local anterior à readmissão. Não filtrar arbitrariamente na UI, não adicionar cache/queue/timer/scheduler.

**Release:** ambos PR #6 e #8 estão em draft, main e build 56 inalteradas. R4 FAIL e B03 FAIL são **vereditos históricos relatados na linha F13**, não ensaios desta nova branch. B06 NOT_RUN. PR #8 declara Swift/iOS NOT_RUN e inclui REDs intencionais. **Não promover, integrar às cegas ou declarar release aprovada.**
