# FeedMine iOS — Phase 3R10

Implementation plan (original 3R10 plus session/store resumption contract):

1. Build a versioned standalone iOS 18/Swift 6 Xcode project, referencing the parent local package. Keep root Package.swift/Package.resolved and Sources untouched.
2. Compose one persistent RuntimeDatabase and one trusted fixed-ID RSS configuration. Restore published history before any HTTP; use existing ColdFeedBootstrap for absence and share its AcquisitionCoordinator with FeedRunwayDriver.
3. Associate one FeedSession/FeedScreenStore/driver lifetime. Forward viewport asynchronously through FeedPresentationHandoff; install through Store and retain Runtime ordering errors. Lifecycle checkpoints the current Session. Explicit replacement closes the old association and creates a new empty Store; old callbacks cannot enter the new association.
4. Verify S1–S7 with real persistence/session/publication integration tests, and XCUITest with real feeds. Measure simulator phase/geometry/velocity and delivery to Runway honestly. Test local restore and network-blocked relaunch.
5. Run package regression, simulator build/test/launch, scope check and independent review. One commit and branch push; no main integration.

App resources and transport bounds are explicit development configuration, not a catalog or another acquisition pipeline. Media rendering remains deferred to 3R11. Runtime-produced projection provenance is neither persisted nor generated by this app.

## Associação e oportunidades

Uma FeedAssociation possui uma Session e um Store. A instalação chama Store.install; frescor/provenance permanecem no Runtime/PresentationState. Scroll e foreground usam o driver real e preservam a associação. Background salva o cursor e informa consumo inativo. Sem apresentação, um foreground oferece outra oportunidade finita ao Cold, sem timer ou retry automático. Uma chamada Cold pendente não é duplicada.

replaceSession é uma operação explícita de composição: desassocia, encerra o driver/transport anteriores e só então cria outra associação com Store vazio. Callbacks antigos continuam apontando para a associação encerrada e não instalam. A provenance não é persistida nem reconstruída no app.
